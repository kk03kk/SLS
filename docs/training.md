当前本地模拟器为审计修复后的来源，未签发全幕资格；服务器作业934705沿用旧冻结来源，于PPO backward显存不足退出，未完成20M。完整下载与归档见下方产物说明及status.md，尚未续训。旧Act1–2工件和入口库保留原SHA；后续使用新来源必须另做资格与训练准备，不能重写checkpoint元数据或用新source标记旧入口库来绕过门禁。


## 实验合同

当前已实现的正常开局短对照配方为A（原PPO、domain标准化）、B（仅改global标准化）、C（仅加短价值适配、仍domain）。全部从同一90M父权重显式迁移为v6，100%正常Neow开局，以第二幕Boss击败为终点；无入口库、无第一幕保持约束、无人类牌组标签。学习率、λ、熵、奖励、网络规模及序列配置沿用原配方；每50次更新在一个序列块上测共享梯度，可通过`gradient_diagnostic_interval=0`关闭。标准化模式、适配配置及完成状态都受严格恢复合同约束，旧checkpoint不通过补写元数据升级。

C组默认采集512个完整episode，按episode顺序将前384局用于拟合、后128局用于验证；不按成功、资源或到达幕数筛选。目标是实际训练奖励（含原势能差分）的完整未折扣累计回报，不读取旧价值自举。只拟合`value_head`全部参数，独立Adam为lr=1e-3、batch=512、最多8轮；将未适配头作为第0轮，采用验证MSE严格最低的轮次。没有改善则记录`NO_ADAPTATION_GAIN`并停止C，不自动转成A或启动PPO。适配最多524288次实际模拟器调用；失败调用及进程恢复后的重做也消耗预算，超过上限明确失败并保留journal。采集每局/每64步及停止时保存进度，拟合每批原子保存；拟合异常不发布半批，正式PPO不发布半次更新。

首轮每臂最少新增1M决策，配置先按64×256 rollout向上取整为1015808。C的适配交互计入新增预算，剩余PPO部分再取整到完整rollout，因此最终总数可能多出不足一个rollout；报告`parent_decisions`、`new_decisions`、`value_adaptation_decisions`和`ppo_decisions`。模型学习效果不能由CPU小测试或价值验证MSE改善推断。20M/40M仅登记为后续预算选项，无自动启动、延长或预算晋级。

配对PPO训练初始seed为210000000，适配种子为[260000000,260000512)，二者独立；周期开发集为[8000100000000,8000100002048)，独立开发确认集为[8000101000000,8000101004096)。最终[9000000000000,9000000004096)保持封存。清单扫描既有配置及实际JSON/JSONL（含压缩）记录以拒绝冲突；同一初始seed不保证不同策略后续经历相同轨迹。比较固定终点的正常开局联合通关，周期峰值单列，第一幕到达用于解释，不能单凭其下降强制维持旧策略。

代码准备、规则资格、服务器运行和学习效果分别报告。当前来源已独立通过72项机制/流程义务与8条自然canary的Act1–2有界资格；原始无条件差异与独立时钟条件匹配分开保留。新配置绑定`tests/fixtures/evidence/act12-normalstart/`中的新资格与weights-only来源桥接，不继承旧混合训练资格，不允许旧环境精确恢复。全803项内容及心脏资格继续暂停；服务器显存修复、正式规模恢复及学习收益尚未验证。

自主学习原则：由用户确认，项目主线让智能体从规则、合法公共信息及实际胜负中学习，不引入人类卡牌评级、固定拿牌表、人工战术示范或人工专家策略来规定打法。完美打击等内容的价值由实践结果判断，出现频率只能用于观察，不能据此禁止、惩罚或设置教师标签。现有楼层/生命势能差分属于明确的人为中间设计，后续需单独审查其优化影响；不能宣称当前训练只有终局反馈，也不自动叠加新的战术奖励。

当前讨论采用90M父权重显式迁移后的v6作为固定基点，正式目标为正常Neow开局至第二幕完成。允许第一幕构筑、资源消耗、路线及到达率为该目标改变；第一幕指标用于解释，不能硬性要求维持旧任务胜率或旧策略行为。现有失败作业的`selection_progress_guard=false`，故不能把其失败归因于并不存在的硬性第一幕选模门槛。父策略约束不作为默认解决方案。

下一步先在本地CPU复核已有日志、目标切换后的价值适配、按幕实际决策/优势/策略与价值梯度、探索程度以及入口记忆处理，再按明确假设安排服务器短对照，出现可复现收益才扩大预算。自动课程只能依据智能体自身实践与学习进展安排真实状态的练习，保持合法前缀、正常资源及独立正常开局评估；重访状态时重新采样，不将旧轨迹直接当作当前PPO样本。自生成搜索可作为远期算法研究，不是直接套用围棋方法；须处理本游戏隐藏信息与随机性，不读取实际隐藏未来。此处是讨论原则，尚未修改训练配置或启动实验。

主要研究目标由任务合同明确登记：角色、Ascension、正常开局分布、终点及成功判据。当前工作围绕战士 A20，Act1/Act2 是阶段目标，完整 Heart 目标还涉及双 Boss、三钥匙和 Act4。

训练种子、周期选模种子、开发确认种子和最终保留种子分开。保留集在候选确定前封存；周期峰值不自动成为独立确认结果。对照模型须使用相同环境、runtime、种子和评估方法。

固定终点与周期所选 checkpoint 分别报告，不能因文件叫 `final` 就认定它是训练终点。循环终止计为策略失败并披露，backend 错误、超时与执行故障另外核对。条件子组和不同种子块的百分比不能替代合法配对比较。

## 续训与迁移

- 精确恢复要验证并保留权重、Adam、worker、RNG、记忆、配置与 runtime 合同。
- 相邻任务的 weights-only 迁移重新初始化优化器和环境状态，不称为精确续训。
- native 规则、Observation/Action、词表、reward、PPO、布局和软件栈变更按合同检查；没有证据时不添加兼容豁免。
- 整理后的证据路径解析属于训练实现的来源变化，已有作业不能绕过旧 source gate 直接恢复；未来提交须重新核验相应合同。

历史 `configs/`、manifest、checkpoint 和证据 JSON 保留原字节及哈希，不通过改 hash 把旧实验包装成当前实验。旧路径可由 `src/sls/evidence_paths.py` 定位到新目录，验证仍核对原始证据字节。

历史934705的20M配置已使用v6角色/字段编码，其余历史配置及模型默认仍保留v5。当前三组继续通过 `warm_start.model_migration = "v5-to-v6-role-bindings"` 显式迁移90M父权重，保留actor/critic旧权重及初始预测；Adam、workers、RNG和循环状态重新初始化，C再单独适配价值头。新模型中的option variant和绑定参数需要后续学习，不宣称已提高第二幕胜率。服务器启动仍须通过实际Linux/CUDA准备及完整规模恢复检查。

## 后续研究与历史讨论

934705的具体重算结果见status.md；以下为下一轮设计建议，不表示已修复、已获服务器资格或已批准启动。

最新讨论确定下一轮主方向：从90M父权重等价迁移的v6重新建立实验，100%正常Neow开局，完整运行至第二幕终点；不延续失败作业的8–9M权重，不采用原50%入口混合课程。原配置和入口库保持历史身份。允许第一幕策略为两幕目标改变，以正常开局联合通关判定收益，不硬保原第一幕通过率。20–40M是有效方案可扩展的预算，不是原配方自动加倍的理由；先本地CPU完成代码与诊断，再按本地验证→GitHub→服务器拉取的流程进行正式规模运行检查和短对照，仍禁止本地GPU测试。

1. **运行闭环修复已在本地完成。** 动作引用改为直接在[B,E,D]输入上gather，避免[B,A,E,D]梯度分配；checkpoint参数布局与架构版本不变。父v5与所选候选分别在独立实例评估，构造不消耗训练CPU RNG，训练器始终保留终点权重/Adam/环境/记忆。更新指标新增批次最大实体/动作/决策数、padding比例和CUDA allocated/reserved峰值。失败时写`training-failures/failure-*.json`，记录阶段、batch、已完成Adam步骤及原latest的SHA/步数；不发布部分更新状态、不自动原地重试，诊断写入失败也保留原错误。完成bundle包含历史失败诊断，恢复后归入`previous_failures`。CPU回归及真实CLI训练→收尾→导出、收尾失败→恢复已验证；服务器Torch2.6/A100正式规模显存与恢复仍待验证，不视为已放行旧934705。按用户要求禁止本机GPU测试。此次没有改变PPO配方、序列长度、minibatch或加入分桶/拆批；若未来正式规模仍需分桶/计算token预算，应另验GRU顺序和PPO权重。`expandable_segments:True`仅为经对应runtime验证的碎片缓解选项。
2. **先确认下一轮环境身份。** 当前90628cf…与旧27eba742…不同，启动前需要当前Act1–2范围的差分/输入/恢复资格；100%正常开局不需要重建入口库。模型仅以明确weights-only方式迁移，重置训练状态。保留旧实验全部身份。若专门复现旧失败，必须恢复对应冻结源码及runtime并检查原checkpoint合同，不能使用本地新native冒充精确恢复。
3. **用短对照拆开价值适配与优化失稳。** A/B/C实现与首轮至少1M决策的合同见上文；不以极少数胜局宣称优胜，有效候选再用独立训练随机种子和开发评估确认。分域标准化会重新加权不同屏幕的学习信号，旧记录约44–51倍尺度只是检查线索，不能据此断言数值错误或必然失败。后续学习率/更新KL、探索或记忆burn-in均是另行验证的变量，本轮不同时引入。价值适配不会产生新的成功策略，历史critic20M人类中断且无固定终点，也不是适配有效性的证据。
4. **先把正常开局数据量与学习信号测清。** 记录每幕实际决策、到达数、条件成功与联合成功、价值误差、优势原始尺度、探索熵及策略/价值梯度贡献。100%正常开局使构筑、Boss遗物和资源决策都接受两幕结果反馈，但第二幕样本量可能下降，需实测；第一幕到达率是诊断指标，不是必须保持的硬门槛。原1493入口库保留作历史诊断，不作为本轮默认训练起点。自动重访或搜索仅在正常开局路线无法建立有效学习后另立对照，不注入人类卡牌评级，不把旧动作/logprob直接加入当前PPO。奖励维持胜负目标与终止势能归零，不能无对照叠加拿牌、金币、爬楼奖励。
5. **再做信用分配与模型消融。** gamma=1时，lambda=.98的TD残差权重有效长度约50决策，距256步权重约0.0057；这不等于return被折扣或GRU只记64步。序列64是截断BPTT边界，未做burn-in会使用旧权重记忆作为块起点。只有在价值与稳定性可控后，分别试burn-in/更长序列、全局与按域优势标准化、低方差KL诊断及v5/v6对照。旧lambda=.98/1研究未证明收益，不直接重复大预算。当前新增绑定参数已学习，但未证明v6优于v5，不优先扩大网络。
6. **用独立确认限制无效长训。** 当前三组每约0.25M查看正常开局联合通关、到达率及学习诊断；不采用曾讨论的第一幕下降5个百分点早停规则，也不要求保留旧打法。通关数个位数时，不以value loss下降或单个周期峰值续长。首轮4096个独立开发确认seed只提供相应样本量的证据；若小差异仍不确定，再单独登记更大的新确认集，不反复窥看最终保留集。greedy与随机采样策略的指标不能混称；额外随机策略评估属于后续研究，本轮未实施。
