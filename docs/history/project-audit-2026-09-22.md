## 已修复问题

| 问题 | 原有影响 | 修复与回归验证 |
| --- | --- | --- |
| 轨迹比较不核对权重身份 | 同一提交下不同权重可能被当作相同策略 | 采集元数据增加 `model_sha256`，比较时要求双方存在且一致；覆盖不同/缺失哈希及真实采集输出 |
| 空轨迹、错误后端角色可通过比较 | 没有执行证据，或两份模拟器日志，也可能输出通过 | 要求非空、simulator/original 角色正确；CLI 退出码统一使用最终 `passed` |
| 循环策略输入比较不完整 | 上一步动作/奖励及编码输入差异可能未被直接定位 | 比较 previous action/reward 与 policy input hash，记录首个差异 |
| 验收计数不保证独立性与完整性 | 同一报告重复传入可凑满 30 份；局部轨迹可冒充完整轨迹；仅凭 seed audit 的通过标记可放行 | 检查完整终局、边界数量、后端/契约、seed 与来源哈希；按 64 位种子身份及来源去重；核对 seed audit 完成数、范围、失败列表和 schema |
| Boss 遭遇名与怪物名不一致 | AUTOMATON、CHAMP、COLLECTOR、DONU_AND_DECA 实际进入战斗却不计覆盖 | 补充遭遇到实体的映射，四组回归用例覆盖 |
| 环境池部分启动失败未回收 | 后续进程启动失败时，先前的子进程与管道遗留 | 失败时关闭当前管道并回收已启动进程；两类进程池均有注入失败测试 |
| 环境池关闭和单槽索引处理不一致 | 重复关闭可能抛异常；负索引可能悄悄操作最后一个环境 | 关闭操作可重复调用；拒绝负索引；拒绝非正数及非有限超时 |
| VectorWorkerPool 诊断写入掩盖原异常 | 磁盘/目录故障时，看到的是诊断写入错误而非模拟器原始故障 | 诊断失败仍保留原异常；使用不可写入的目录路径复现 |
| 种子审计动作上限偏一 | 恰好在最后一次允许动作结束的合法对局被报告为超限 | 最后一次动作后仍检查终局；禁止空种子批次与非正动作上限 |

主要修改位于 `src/sls/rl/workers.py`、`src/sls/diagnostics/canary.py` 及三个审计 CLI。没有改变训练目标、奖励公式、模型结构、模拟器源码或已有 checkpoint。
