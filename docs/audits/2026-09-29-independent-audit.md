## 需要修正或继续处理的部分

1. **环境身份链。** 训练环境 `95e5b651…`、平台期基线 `470acd31…`、当前 HEAD `1e30bb6c…`
   三代身份，两份文档各自称自己是"当前"。两者之间的 native 差异只有 standalone 卡牌奖励的
   7 行映射修复。**已在 README 中并列记录两次测量并声明环境身份。**
2. **目标函数与指标不等价。** 成功 +1、失败 `−1 + 0.8·floor/16` 的目标在实测回报 0.70645 处
   **无差异**于"85.32% 通关、其余全部死在第 1 层"的策略；一次胜利等价于 24 层进度深度。
   即约 8 个百分点的通关率落在该目标的偏好之外。这是当前最值得改变的单点。
3. **种子块效应。** 同一环境同一模型，`[8e12,+512)` 为 73.24%，`[7e12,+2048)` 为 76.61%；
   后者四个子块同质（p = 0.80），8e12 块显著更难（p ≈ 0.0014）。跨块绝对数字不可比较，
   机制（种子→内容映射的均匀性）尚未查清。
4. **评测功效。** 512 种子对 3pp 效应的配对功效只有 33%（需约 1,750 种子）；计划中的
   2M 决策对照实验因此难以给出结论。该测算被 Neow 干预实验实测印证（真实 4.5pp 效应 p = 0.0616）。
5. **选模保护门失效。** `selection_progress_guard` 在 ACT1 配置下无法拒绝任何候选
   （`reached_act2/3` 恒为 0，`backend_errors` 从不递增，`timeouts` 结构上不可达），
   选模实际退化为"复用 512 种子上取最大值"。已修复并加测试；修复只应在新作业生效。
6. **训练通量。** 14M 步阶段 38.67 小时中，GPU 策略前向仅占 6.5%，观测编码 26.9%、
   Python 记账 22.7%；99 decisions/s。`approx_kl` 约 0.002 而 `target_kl` 为 0.02，
   855 次更新从未触发 KL 提前停止；梯度裁剪 100% 命中。
7. **模拟器残留差异。** 伤害修正顺序被写死，原版按能力获得顺序遍历，两个方向都会出现
   （`BattleContext.cpp:2848-2881` vs `AbstractCard.java:2215-2235`）；怪物逃跑后仍可掉落药水
   （`GameContext.cpp:1923-1925` vs `AbstractRoom.java:587-591`）；COMBAT_REWARD 边界上
   未点开的卡牌身份被项目自己的 Oracle 补丁泄漏进观测。
8. **复现缺口。** 热启动 50M 权重不在 Git 也不在 56M 归档内；配置引用的 benchmark 已不存在；
   无 `latest.pt` 故无法精确续训；配置摘要对行尾敏感（已在代码中改为规范化哈希）。

## 已否证的假设（记录以免重复投入）

用 `tools/intervene_policy_decision.py` 对 Neow 决策做强制选择干预（512 配对种子 × 5 臂）：
贪心策略下 Neow 在 509/512 局里字面上等于"永远选第 1 项"；perfect-foresight oracle 上界为
93.55%（+20.3pp）。但 `tools/audit_neow_headroom.py` 用公开 offer 标志做按种子分组的
交叉验证后证明：**从 offer 学出的条件策略（69.5–70.1%）比"永远选 1"（73.05%）更差**
（logistic p = 0.033），最好的单特征规则仅 +0.97pp。因此该 headroom 几乎全部来自预知未来，
**Neow 的常量选择是当前信息下的最优解附近，不是缺陷**。项目文档原有判断（"集中本身不等于
选择错误"）成立。这也削弱了"信用分配损坏"这一推论，应降级为待做的一次消融。
