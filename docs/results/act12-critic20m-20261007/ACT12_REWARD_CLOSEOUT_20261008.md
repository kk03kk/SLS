# Act1+Act2 模拟器本次收尾：盗贼奖励

当前结论：**新发现的盗贼药水规则缺陷已修复，五项奖励义务的 15 次真实 TheCity 受控对照完成。** 这关闭本次重新开启的义务，不表示整个 Act1/Act2 内容全部认证，更不表示修复提高了模型胜率。

## 实际问题与修复

原版 `AbstractRoom.addPotionToRewards` 在普通战所有怪物都逃跑时，将基础药水概率留为 0；药水保底不能把它提高。White Beast Statue 随后覆盖为 100，奖励数量上限随后覆盖为 0，概率 RNG 仍消耗。native 原来虽抑制金币，却仍使用 `40 + potionChance`，可能错误掉药水并改变保底及后续随机序列。

修复仅在 `GameContext.addPotionRewards` 的普通战全逃跑条件下使用 0。已有战斗结束逻辑的 `suppressCombatGold` 提供此条件。没有修改训练 reward objective、PPO、网络或训练分布。Smoke Bomb 仍走其原有构造、隐藏奖励和胜利回调路径，没有统一屏蔽“逃跑奖励”。

旧源码、旧 native 二进制、三个修复前失败输出及真正失败的回归日志均保留在本地。对同一 stock RNG，旧实现三例药水/保底/RNG 比较失败；修复后通过。

## 工具问题独立处理

旧隔离场景虽设置 Act2 标签，却仍使用 Exordium 地牢，无法据此认证 Act2 卡牌升级概率。补充 validation-only `parity_dungeon 2`，调用原版 TheCity 构造器，并核验实际地牢类、ID 和房间。新不可变清单 `fullrun-thief-city-r1.json` 明确要求此上下文；旧捕获继续保留药水分支的局部资格。

重放最初借用续接结构时带入历史卡牌保底 3；改为保留新局初始值 5。原版 AbstractDungeon 初始化字节码独立支持 5，局内没有先前战后奖励；不是调整游戏规则来迎合 native 输出。初次失败输出 `native-city-a-after-r1.json` 保留，修正后输出另存 r2。

盗贼可能提前一回合逃跑，采集器现允许在声明的稳定奖励边界停止动作脚本；重放核验实际动作是声明脚本的前缀。旧超出战斗边界而失败的批次不计通过。另有首次不兼容 JVM 参数启动失败，保留日志与恢复结果，不算游戏机制失败。
