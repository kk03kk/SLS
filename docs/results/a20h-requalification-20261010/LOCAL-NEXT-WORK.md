# 等待 NUS 结果期间的本地工作顺序

日期：2026-10-10。目标仍是稳定通关战士 A20H；本阶段使用 DL / CPU、小规模验证，不改运行中的训练、权重或恢复契约。此前提交的 job 927398 是停训模型评估，提交记录 training=false；没有新服务器状态时，不推断任务仍在运行或已结束，也不另启训练。

## 1. 优先补齐 A20H 模拟器证据链

已有版本绑定的地图、钥匙、双 Boss 与 Act4 入口证据，但完整 A20H 尚未取得资格。按以下顺序推进，遇到第一个真实行为差异先隔离复现，保留失败归档，再决定是否修改生产模拟器。

1. **Act4 连续流程**：从双 Boss 后的实际三钥匙入口继续到休息、商店、Shield/Spear、奖励和 Heart。先验证历史原版归档的 JAR、场景、实际上下文、完成与恢复身份；孤立的 Heart 战斗不能替代完整转幕链。缺少边界再使用新 namespace 补采原版。
2. **Heart 战斗和结局**：覆盖 Beat of Death、Invincible、强化周期、状态牌、药水及死亡/胜利后的行动与 RNG；比较实际动作后的稳定边界，并从每个 checkpoint 重放完整剩余轨迹。观察次数或样本耗尽标为未完成，不能记死亡。
3. **钥匙自然获取和地图**：已验证八种初始组合的门槛，仍须连接休息换 Ruby、宝箱换 Sapphire、燃烧精英掉 Emerald 的实际后续路线，检查重复持钥匙、掉落、候选动作与 RNG 消耗。未解锁最终幕的路径保持独立缺口。
4. **召唤及尸体状态**：继续追踪 Reptomancer、Gremlin Leader、Cultist、Deca 等未消除的 raw 差异，检查目标、槽位、动作及后续召唤。公共投影一致不替代原始状态和后续行为验证。
5. **自然轨迹转移**：先用短、固定 seed 的实际路线发现首次分歧，再扩展覆盖。受控强牌组用于定位规则，不能当作自然构筑能力或胜率证据。

验收逐层记录：原始状态、完整公开 Observation、合法动作、编码、RNG、终止原因、checkpoint 后缀。原版 UI 与 native 自动转场的差异单列，不折叠成策略已对齐。每份证据绑定 native 源码/二进制、Oracle/原版 JAR、manifest 和报告哈希；生产修复后重新验证，不能把旧环境通过结果迁移为新环境通过。

## 2. 并行推进模型能力诊断

只读使用现有冻结模型和已经完成的诊断轨迹，定位失败主要来自战斗决策、构筑分布、策略循环还是 value 与回报不匹配。对同状态按相同公开历史重建各模型自己的循环记忆；原版额外 UI 步与 native 折叠界面对记忆的影响需独立检查。

critic 只与完整终止轨迹的实际 shaped return 比较，明确奖励目标、策略和 horizon；截断样本单列，不把 value 当通关概率。原版校验的受控初态与自然状态库分开保存，禁止把人工强构筑进入生产课程。

这项工作可在服务器返回前准备工具与小样本证据。服务器结果到达后，再检查同环境、同 seed、同预算的冻结模型比较；不能用不同环境的局部诊断代替正式胜率结论。

## 3. 最后准备下一训练实验

根据前两项证据选择单一主要干预点。自然可达后段状态课程和成功经验利用仍是候选，但只有相关状态的模拟器行为、公开历史、恢复后缀和奖励目标得到验证后，才提出具体训练配方。

本地可以提前定义数据来源、状态分层、训练/验证 seed 隔离、对照组、计算预算和停止标准；暂不接入生产训练，不同时改网络、奖励与优势标准化。性能优化使用固定轨迹 CPU 基准和语义等价检查，仅报告本地结果。

## 用户下一步

目前无需服务器操作。本地完成上述可复现证据与验证后提交研发分支；需要 NUS 数据或新实验时，另提供固定 commit 的拉取、检查和运行命令。在收到实际服务器结果前，不建议仅增加训练步数作为主要推进方式。
