## 证据规则与安全边界

1. 每份结果绑定 stock JAR、Oracle 源/产物/场景资源、native 源/产物、seed、初态、动作和原始 capture SHA256。运行前检查 seed 命名空间及输出冲突。
2. 只有初始场景允许受控设置；后续由原版真实动作推进。受控、自然、静态核对、匹配、差异和未完成分别报告，不以注入状态补自然覆盖。
3. 运行本地原版复用现有备份、owned-process 管理及恢复 journal；检查游戏未运行，退出后验证保存、配置及模组恢复。原工作区待提交文件继续按原快照复核。
4. 新确认缺陷形成最小复现、最小修复和独立来源；适当测试及原版重放通过后独立提交。环境改动不原地恢复旧 run，不添加兼容白名单。
5. 没有差异不等于穷举证明；列出字段、动作、组合和路径覆盖缺口。超出步数/工具能力报告未完成或不支持，不伪记游戏失败或通过。

## 服务器结果回来之后

先核验模型、环境、seed、终止及完整性，再做四模型逐 seed 配对分析：Act1 保留、两幕联合成功、循环、真实 Boss 进入及进入资源，避免只看 value loss 或最高开发成功数。

据此选择 weights-only 起点并注册小预算对照。优先候选是正常开局与自然后段课程，网络、奖励和 PPO 参数保持同一；正常开局能力保留及额外前缀计算成本是必报指标。成功经验利用、梯度隔离或其他算法改动分别对照，不同时叠加。

现阶段无需用户新增服务器操作。需要服务器 profiler、采集或实验时，先本地完成代码及验证并推送，随后提供绑定 commit 的明确拉取和执行命令。完整 A20H 长训须以本轮环境资格和小预算能力证据为基础。
