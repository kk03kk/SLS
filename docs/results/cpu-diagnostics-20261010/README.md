## 自然轨迹、同状态与循环

诊断 seed 为 `[132100000,132100032)`。每个模型执行 32 条正常开局 greedy Act1–2 轨迹，共 96 条、21,509 个公开决策。采集前检查配置和 run 注册，另核对原工作区已有的 230 个报告文件，没有命名空间冲突。每一步的 Observation、候选顺序、实际动作、raw/shaped reward、value 和完整公开历史均保存。native checkpoint 单独存放在 private 目录，不进入策略输入。

|---|---:|---:|---:|---:|---:|
| parent90 | 20 | 1 | 26 | 5 | 20.80 |

牌组大小本身没有显示明显膨胀趋势，不能把后续失败简单归因于“牌组太大”。结构化 summary 同时保存入口卡牌、遗物的完整计数；三个模型到达后段的状态分布不同，直接比较自然后段表现会混入选择偏差。

8 条循环全部发生在 floor 17 的 `CARD_REWARD` 主牌组选牌页。尾迹明确出现同一个 `select-card:n` 连续选择/取消，已选数量在 0↔1 或 1↔2 间反复变化。完整历史和 32 步动作/已选状态尾迹均保留。它支持将 Act2 入口的多选与确认行为作为具体研究干预点，不能据此擅自替策略强制确认，也不能把这项证据单独解释成新 native bug。

64 个状态采用按 act/screen/敌人组合的联合层、固定 SHA256 排序轮转选择：Act1 43 个、Act2 21 个；COMBAT 58 个，MAP、SHOP、REST、COMBAT_REWARD、TREASURE、EVENT 各 1 个。自然轨迹遇到了全部六种 Act1–2 Boss，但所选状态缺少 Guardian、Champ。所选状态没有 NEOW、CARD_REWARD、BOSS_REWARD、ACT_TRANSITION；所以本轮同状态结果不能检验这些界面上的多模型差异。没有用注入状态补齐覆盖。

自然公开选择源覆盖包括 GENERATED 57、DISCARD 224、HAND 20、DRAW 2、EXHAUST 1 个决策，以及 MASTER_DECK 323 个决策；这些数是决策帧数，可能包含同一选择过程的多次点击。summary v2 修正了 v1 只统计 choice token、遗漏直接引用 deck 实例的 grid 选择的问题；原 v1 派生报告保留，使用 v2 作覆盖结论。细分事件或卡牌选择机制没有穷尽覆盖，不能把“出现 source 类型”等同于全部分支已验证。

同状态比较完成 64×3 次独立续跑。每个模型从相同公开历史重建自己的 recurrent memory，使用历史动作类别与 raw reward，并验证恢复后的 Observation 和候选顺序完全一致。续跑最多 256 决策：

| 模型 | 完成的续跑 | 完成 Act2 | death | cycle limit | 未完成的诊断截断 |
|---|---:|---:|---:|---:|---:|
| parent90 | 60 | 2 | 56 | 2 | 4 |
| lambda098 | 58 | 0 | 58 | 0 | 6 |
| lambda100 | 62 | 0 | 61 | 1 | 2 |

只有 54 个状态的三个模型均完成续跑；截断没有记为游戏失败，也没有用 bootstrap 伪造完整回报。续跑完成样本之间的均值还含有不同完成集合的偏差，不能用作正式模型排名。

58 个相同 COMBAT 状态中，lambda098/lambda100 的 greedy 首动作有 16 个不同；lambda098/parent90 有 11 个不同；lambda100/parent90 有 10 个不同。对应平均 Jensen–Shannon divergence 为 0.1378、0.07645、0.09173 nats。初始构筑固定后仍存在策略差异，不能只用自然构筑分布解释它们。

额外提取的 3 个 Act2 Boss 战控制状态固定初始构筑、资源、历史及 native 状态，三个模型均死亡。它们没有给出纯战斗能力排名，3 个样本也不足以覆盖资源和构筑质量分布。parent90 的两个条件成功发生在更早状态，其后仍包含构筑与路线选择；因此也不能把这两次成功全部归因于战斗策略。后续课程研究需要收集独立训练 seed 上资源尚可的自然后段状态，并增加“当前战斗结束即停止”的诊断。

## Critic：拟合失败不等于能力增强

完整 MC 使用实际 float32 shaped rewards、gamma=1、真实终止轨迹，不 bootstrap、不把 value 当成功概率。三个模型的实际 PPO critic 目标为 `V + GAE`，rollout 256 步；parent90 和 lambda098 的 lambda 为 0.98，lambda100 为 1.0。随机训练策略、rollout 边界 bootstrap 与本轮完整 greedy MC 的目标不同，必须分别解释。

| 模型 | 初始 value 均值 | 初始完整 MC 均值 | Act1 greedy MC MSE | Act2 greedy MC MSE |
|---|---:|---:|---:|---:|
| parent90 | 0.52454 | -0.97377 | 2.51674 | 2.62411 |
| lambda098 | -1.03197 | -0.97377 | 0.12832 | 0.45679 |
| lambda100 | -1.01254 | -1.03627 | 0.000817 | 0.001814 |

parent90 的 critic 学的是 Act1 horizon，其 Act2 MC 误差不能直接作为原训练 critic 失配证据。lambda100 在全部失败的自然窗口中，接近常量失败回报的 value 已能得到非常小的误差；它没有同时表现出任务能力。这是不能用 value loss 降低替代成功能力的直接例子。

lambda098 的成功轨迹以及更复杂的后段状态使 greedy MC 误差变大，但单个真实回报还混有隐藏随机状态与策略差异，不能据此断言其训练 critic 必然错误。当前证据不足以单独决定 critic20M 的投入。该配方保持原身份，等待服务器同环境结果，再考虑同预算对照。

## CPU 性能与验收

固定基准使用上述 64 状态及每个模型第一条完整轨迹，共 824 决策。7 组 A/B 顺序交替、相同 warmup，分别测量观测校验/序列化、指纹、编码、batch 组装和完整固定动作重放。实体、候选、8 状态 batch 的 padding 逐项保存。

完整重放包含 backend、编码、单状态 batch 和 limiter，**不包含策略推理或 PPO 更新**。这是本机 CPU 结果，不是 NUS 加速结果。每项优化独立通过目标阶段至少改善 10%、完整重放不退化超过 2% 的门槛。

静态字段缓存及禁止字段常量复用：观测阶段 142.058→119.455 ms，改善 **15.91%**；完整 824 决策重放 8269.645→7442.446 ms，改善 **10.00%**。指纹阶段随之改善 4.54%；编码与 batch 阶段没有针对性改动，微小计时波动不作为加速结论。生产提交为 `0cbc64d`。

循环指纹优化复用固定配置的 JSONEncoder，并让标量直接返回，保留原 canonical 排序、ASCII 排序 key、UTF-8 hash payload 和 SHA256。以已采用字段缓存的版本为独立基线，指纹阶段 151.680→124.306 ms，改善 **18.05%**；完整重放 7080.998→6830.031 ms，改善 **3.54%**。生产提交为 `8fbd418`。不能把不同测量窗口中的百分比直接相加，推导整个 PPO 的加速。

直接构造 ASCII/Unicode 双 JSON 文本的原型，7 组指纹阶段 160.987→190.225 ms，退化 **18.16%**，不满足目标阶段门槛，没有进入生产路径。其代码与完整测量留在本地交付包中。完整重放单独测得中位值降低 7.77%，没有用这一指标覆盖目标阶段失败；其他未改动阶段的波动也不作为性能归因。

两项生产优化的语义验收均覆盖 64 个状态、824 个完整重放决策，以及每个决策的 checkpoint 恢复、limiter、合法动作、Observation、编码 tensor、指纹和终止结果。优化后的三个模型完整 greedy 重放也保留原动作轨迹，最大 value 差异均为 **0.0**。所有动态状态仍逐次读取，未引入 checkpoint 兼容白名单。

## 本地验收与历史绑定

CPU 全量测试 **1361 passed、2 skipped**；跳过项分别为旧编码历史权重被现有契约拒绝、CPU 阶段禁用 CUDA。Ruff、词表、独立 native 构建通过，配置检查结果如下。最终明细见 [validation.json](validation.json)。验收中先发现的 4 个失败已在干净 80b 上逐个复现：含中文路径的测试文件缺少 UTF-8、两个旧训练 CLI 替身缺少 critic_warmup，以及归档分析测试没有显式使用已有 missing-export 开关。修复仅涉及测试工件与调用；历史注册操作器源码保持原样。额外复用原工作区的三份 stock Java 投影，逐字节核对后在隔离目录执行相关测试；原始证据文件没有改动。

发布版本 80b 的配置检查为 **35/35**。优化分支为 **34/35**，唯一拒绝是 `act12-critic20m-r1.json` 的 `bound training/native source changed`：训练实现摘要变化会触发现有契约，这是本阶段应当保留的结果。没有改写该配方、注册操作器或摘要白名单。当前分支不是旧 critic20M run 的恢复环境。

## 下一阶段最值得做的事

1. **P0：维持环境与评估版本边界。** 本状态库绑定 80b native；更换模拟器版本必须重新生成自然轨迹和状态，不能恢复这些 private checkpoint 后改称新环境结果。Act3/Heart 的一致性未由本轮 Act1–2 诊断验证；冲击 A20H 前仍需独立的后段 stock parity 门槛。
2. **P1：优先准备自然后段课程。** 在独立训练 seed 上，用冻结强参考策略收集自然到达的 Act2 入口、floor 17 选牌/确认、资源尚可的 Act2 中后段及 Boss 状态。保留整个公开前缀与版本绑定的私有恢复状态。训练 reset 时重算当前模型的历史记忆，不能复制旧模型记忆或暴露私有 native 数据。本轮诊断 seed 和 64 状态仅用于研究定位，不接入训练。
3. **P1：做单一干预、同预算对照。** 首个实验只改变自然后段 reset 分布；先小比例介入，保留正常开局能力监控。网络、奖励、PPO 和优势标准化继续保持基线。正式评估使用独立 seed，分别记录 Act1、Act2、后段进入资源和循环。以成功能力和能力保留决定是否扩大课程。
4. **P2：单独验证成功经验利用。** 用独立采集的多 seed 成功行为研究 recurrent BC/辅助模仿，检查自然开局及后段泛化，再考虑与课程组合。不能把历史成功动作直接当 on-policy PPO 样本，也不能依靠这组极少成功轨迹拟合一个“看起来会通关”的模型。
5. **P2：等待 critic20M 的真实服务器结果。** 核对其环境、actor 是否冻结、MC 目标、预算与正式评估身份后再比较。本轮不改配方，不因为失败样本上的低 MSE 就选模型。
6. **P2：服务器资源利用另测。** 后续在独立研究 checkout 中复测 Python 阶段和整体采集/更新 profile。CPU 微基准无法决定 NUS 的 shard 数、CUDA 利用或总训练吞吐。
